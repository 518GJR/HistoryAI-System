## 路径与根因

1. `POST /api/question` 先调用检索，再将非空结果传给 `generate_answer_result`；响应中的实际模式来自 `get_retrieval_mode()`。
2. vector 检索对全部 35 个来源计算余弦分数并截取 Top K，没有资料充分性门控或阈值。因此范围外问题同样得到 3 个近邻。
3. `AI_PROVIDER=disabled` 时 provider 配置为空，`generate_answer_result` 明确返回 `template_answer(question, knowledge_items), "fallback", []`。
4. 模板在结果非空时把第 1 条候选的 `content` 作为“直接回答”，并遍历全部候选写入答案。秦始皇题因而把无关史前片段用于回答。
5. `used_evidence=[]` 是 disabled/fallback 路径当前定义的返回值，不是模型证据选择丢失。模板确实使用了全部候选教材内容，API 的 `sources` 能逐项对应回答中的原文和页码；但该路径没有在结构化 `used_evidence` 中标记实际采用项，所以仍存在 fallback 实际证据标注缺口。

## 最小通用修复建议（本轮不实现）

将“候选检索”和“可回答性判断”分开：保留 vector Top K 及其诊断来源，在进入任何回答路径前增加统一的资料充分性判定。判定不足时把候选保留为诊断信息，但回答走现有资料不足拒答，并记录明确的判定模式/原因；不得把最近邻本身当成可回答依据。

由于当前没有经过数据校准的相似度阈值，下一阶段应先冻结开发集和未参与调整的验证集，再比较可解释的通用判定信号，例如问题实体/主题是否得到候选原文直接支持、Top 1 与其余候选的相对分离度，以及可允许“无支持”的证据选择结果。阈值或规则必须在开发集确定，并在独立新题上验收，不能依据本次秦始皇单题写死。

同时为 fallback 增加实际采用证据记录：模板使用哪些来源原文，就在 `used_evidence` 或等价字段中明确保存哪些来源被用于“直接回答”和展开内容。该项属于追溯接入缺陷，可独立于自然语言生成方案修复。

建议验收用例：

- 范围内事实题与换问法：北京人用火、仰韶文化，必须继续正确回答并保留来源页码。
- 范围内比较题：北京人/山顶洞人、河姆渡/半坡，双方证据必须进入统一后的证据预算。
- 范围外题：秦始皇、汉武帝、近现代史及非历史生活问题，应保留候选诊断但拒绝用无关教材作答。
- 困难负例：包含“措施、作用、意义”等通用词但主题不在第 1—3 课，防止只靠问句形式误判。
- 边界正例：措辞不同但原文确有直接支持的问题，避免拒答机制过严。
- 两种检索模式使用统一或等价化证据预算后再做正式比较；keyword 当前按知识点计数，vector 当前按来源片段计数。
