# 资料充分性判断最小设计（未实现）

## 1. 目标与边界

本设计用于在“检索完成”与“进入模板或模型回答”之间增加一个通用判断。本轮只完成设计，没有把该判断接入 API，也没有改动 Prompt或回答策略。

判断必须区分三件事：

1. **检索相关性**：候选片段与问题语义上是否相关，用于排序和召回，不等于可回答。
2. **资料支持程度**：教材原文是否能支持问题要求的事实、关系或结论。
3. **最终证据覆盖**：回答实际采用的证据是否覆盖了所有必需要点，尤其是比较题双方。

## 2. 建议的最小组件

新增独立的 `support_assessment` 服务，输入用户问题、实际检索模式和带原文/知识点关联的候选，输出结构化结果：

```json
{
  "status": "sufficient | partial | insufficient",
  "reason_codes": [],
  "required_facets": [],
  "covered_facets": [],
  "supporting_source_ids": [],
  "supporting_knowledge_ids": [],
  "unsupported_facets": [],
  "method": "interpretable-v1",
  "calibration_version": "development-set-v1"
}
```

这个结果先决定是否允许进入回答，回答完成后再对 `used_evidence` 做覆盖复核。检索候选始终保留，但只有通过支持判断并实际用于回答的原文才能进入 `used_evidence`。

## 3. 具体判定方法

第一版优先使用当前项目已有组件，不下载新模型，不调用外部服务：

1. 从问题中识别最小“所求要点”，仅保留事实/原因/过程/结果/作用/意义/确定性/比较双方等少量通用类型，不建立题目专用规则表。
2. 利用已有稳定知识点 ID、标题/别名、`dimensions`、`qualifiers`、`certainty` 以及来源—知识点关联，把原文映射到可支持要点。
3. keyword 保留现有基线，不依赖向量模型或索引才能工作。vector 的余弦分数只是候选相关性信号，不解释为事实支持概率。
4. 是否足够由“要点覆盖组合”决定，而不是一个未校准的全局相似度阈值。如后续确需分数边界，须先用教材核对过的多类开发题校准，分别记录错误放行和错误拒答，不根据单个失败题设置。
5. 回答生成后，根据 `used_evidence` 重做一次覆盖检查；候选阶段双方都被检索到，不代表最终回答已覆盖双方。

实体字面命中不作为必要条件。别名、换问法和自包含代称可以通过知识点关联与已有语义检索进入支持映射。无上下文且指代对象不明的问题应记录为无法确定，不猜测实体。

## 4. 不同问题类型

- **事实题**：至少一条原文直接支持所求事实或对应结构维度。“主题相关”但未说明所求结论时不放行。
- **换问法/别名**：依赖知识点关联、标题别名和语义检索候选，不要求问题实体在原文中完全同形出现。
- **比较题**：拆为“对象A＋所求维度”和“对象B＋所求维度”两组要点。候选和实际证据都必须覆盖双方；只有一方时不能生成完整比较结论。
- **确定性问题**：除了事实支持，还必须检查原文和限定词。教材仅说“可能”时，不得回答为“已经确定”。

## 5. 部分支持与模型不可用

建议默认政策：

- 如果缺失的是核心结论、必需条件或比较一方，拒绝给出完整结论；可以明确说明当前教材只支持哪一部分。
- 如果核心问题已有支持，仅附加延伸缺失，允许回答可支持范围，并结构化记录未支持要点。
- 外部回答模型不可用时，模板只能消费已通过支持判断的原文。如果没有足够原文，返回资料不足，不用近邻模板假装回答成功。

“部分支持时返回可支持范围”会改变回答产品行为，实现前建议确认这一选择。

## 6. 与后续教材约束生成的衔接

后续自然语言生成直接接收本服务产生的“可支持要点＋支持原文＋限定词＋未覆盖要点”，不再自行判断候选是否充分。Prompt 层只负责用可用证据组织表达，回答后覆盖检查仍以结构化 `used_evidence` 为准。这样可以让模板基线与自然语言生成共用同一套支持与追溯逻辑。

## 7. 工作量、局限与验收

预计最小实现包括：一个判定服务、API/历史诊断字段、事实/换问/比较/确定性与部分支持测试、开发题教材支持标注和独立验收脚本。不包括新模型训练、大型规则库、新向量库或前端改造。

已知局限：当前结构化维度和知识点关联仍需人工核对；双向量模型不能完成严格文本蕴含判断；长问题、隐含前提和无上下文代称可能进入“无法确定”。如解释性基线在开发集上仍大量误判，可后续评估本地中文 cross-encoder/NLI 模型；代价是额外下载、CPU 延迟、许可证核查和新的校准工作，本轮不引入。

开发集必须先核对教材能否支持参考结论，统计：

- 错误放行：资料不足却进入回答；
- 错误拒答：资料充分却被拒绝；
- 比较题候选覆盖但实际证据缺少一方。

所有已在开发过程公开的问题只能作为开发题。规则、配置和判定口径冻结后，再准备未参与调整的新题做独立验收；独立题首次运行结果应原样保存，不用于反向修改同一版方案。
