# PROJECT_PLAN.md

## 1. 文档目的

本文定义 HistoryAI-System 的建设范围、阶段顺序、完成条件和后置项。当前代码状态和验证证据见 [../PROJECT_STATUS.md](../PROJECT_STATUS.md)，运行入口见 [../README.md](../README.md)。

## 2. 总体目标与当前里程碑

系统总体目标是面向中小学学生，集成 ASR、RAG、LLM 和 TTS，建设可追溯的历史教材知识库，并支持知识点覆盖检测、学生提问标注和基于小测证据的掌握情况统计。

教材总体建设范围为依据 2022 年版课程标准修订的新修订人教社统编初中历史五册：七、八年级上下册及九年级上册。九年级下册不纳入。具体教材版次、ISBN 和资料身份尚未核验的部分标为“待补”，不得编造。

五册是总体建设方向，不代表已经完成，也不构成当前阶段全部工作的前置条件。首个实现与验收范围固定为 **七年级上册第 1—3 课**。项目最终完成的教材范围按实际成果如实记录。

## 3. 已确定原则

### 3.1 教材数据

- 已确认的 48 主题知识清单作为七上第 1—3 课试点基础稿。
- 保留“册—课—教材小标题—知识点”层级，每个知识点使用稳定 ID。
- 至少记录材料类型、教材页码、PDF 页序、来源片段和限定词。
- 重点整理事件、制度和技术成果的原因、内容、结果、作用、影响及意义。
- 不补写来源中没有依据的结论，保留“约、可能、之一、相传”等限定词。
- 版次、ISBN 等未核验字段可以留空或标为待补，不阻塞第 1—3 课试点。

### 3.2 演示数据与教材数据

- 原有 15 条通用知识作为演示数据保留，不得称为正式教材数据。
- 教材实验默认只使用教材库。
- 两类数据的目录、标记或运行时切换方案在 A 阶段根据现有架构确定。

### 3.3 存储与数据库

- 当前优先目标是让试点教材数据能够稳定加载和检索。
- A 阶段不要求同时扩展为完整数据库迁移工程。
- 确定实际存储方案和 schema 变化后，再判断是否需要迁移工具。
- 导入方案应保持稳定 ID、可重复执行和来源字段完整，不能静默混入演示数据。

### 3.4 检索与来源

- 保留当前关键词加权检索作为基线。
- A 阶段先完成教材数据检索和来源贯通；通过后再增加轻量向量检索并设计对照实验。
- 检索结果、API 响应和前端展示应传递足以核对教材的来源信息。
- 检索命中不等于学生已经学习、覆盖或掌握该知识点。

### 3.5 测试与评估

- 2026-10-21已建立30题修复前初评基线，固定保存原题、参考要点、来源页码、评分规则、原始回答、实际证据和初评结果；该基线不因后续修复而覆盖。
- 当前30题是阶段性浏览器初评，不作为系统整体准确率，也不等同于约100题的后续扩展评估。
- 后续用于修复与调试的题目和未参与修复的新题必须区分；正式测试题不得用于调参。
- 功能测试通过、检索命中、模型回答正确、人工评分合格和真实服务联调通过是不同证据，不混写。
- 评估计划包含回答正确性、完整性、依据一致性、表达适切性和资料不足处理。
- 不生成虚构实验数据；所有结果必须来自可复查的实际运行或人工评分。

### 3.6 学习记录与掌握情况

- 后续知识点标注和覆盖统计基于稳定知识点目录。
- 覆盖统计需区分“提问涉及”“系统检索命中”“已学习”等事件。
- 掌握情况以小测作答为依据，不使用提问次数直接推断。
- 第一阶段考虑使用受控匿名学习者 ID；登录注册后置。
- 小测题型、评分方式、掌握等级和最低证据量尚待确定。

### 3.7 真实语音联调记录

- 用户此前确认2026-10-03完成真实联调；本轮未复测；仓库待补正式验收记录。
- 后续记录联调环境、供应商与模型、音频格式、操作步骤、结果截图及异常说明。

## 4. 阶段计划与完成条件

### A. 七上第 1—3 课教材数据及可追溯来源接入（已完成，2026-10-15）

目标：建立可继续扩展的教材数据基础，不提前展开向量检索、全面迁移或学习统计。

完成条件：

1. 七上第 1—3 课试点数据能够通过明确、可重复的方式稳定加载。
2. 数据包含稳定知识点 ID、册、课、教材小标题、材料类型、教材页码、PDF 页序、来源片段和限定词字段。
3. 事件、制度和技术成果按实际资料记录原因、内容、结果、作用、影响或意义；无依据字段不补写。
4. 演示数据与教材数据能够明确区分，教材实验默认不混入演示数据。
5. 教材来源经过检索、API 响应传到前端，并能定位回相应教材资料。
6. 原有文字问答、语音接口、模板 fallback、知识梳理和问答历史保持兼容。
7. 为数据加载、检索和来源传递增加必要测试，相关测试通过。
8. 如版次或 ISBN 尚未核验，明确标为待补，不使用猜测值。

完成记录：独立教材 JSON 已按原 48 个知识点 ID 接入；教材/演示模式已隔离；教材来源已贯通检索、API、历史快照和前端；离线后端测试与前端构建通过。真实 MySQL、真实外部模型/语音服务和浏览器端到端流程本轮未复测。2026-10-22 已开始 B 阶段并完成第一版向量检索实现及小规模真实本地验证，但尚未形成正式实验结果；C—E 阶段未实施。

### B. 开发题验证、轻量向量检索与教材约束回答

完成条件：

1. 建立独立开发题集并标注期望知识点或来源。
2. 当前关键词检索作为可复现实验基线保留。
3. 在现有教材片段上实现一种轻量向量索引方案，必要时增加混合检索；向量条目必须保留知识点 ID、教材页码、PDF 页序和来源片段映射。
4. 固定 Top K、评分和日志格式，使用同一开发集与关键词基线比较策略。
5. 明确并实现教材约束的自然语言回答方案，回答能够直接回应问题、保留限定词并适合中小学生理解。
6. 现有“模型选择证据＋后端原句组装”保留为回答基线，不将其等同于自然语言生成方案。
7. 不使用正式测试集调参，并记录失败案例和策略边界。

### C. 知识点标注、覆盖统计及小测掌握统计

完成条件：

1. 学生提问和系统回答可关联稳定知识点 ID。
2. 覆盖统计基于正式知识点目录，并区分提问涉及、检索命中和实际学习事件。
3. 使用受控匿名学习者 ID 区分学习记录。
4. 建立最小小测、作答和评分数据结构。
5. 掌握统计只使用已定义的小测证据，规则、阈值和不确定状态有文档说明。

### D. 扩充教材范围、固定正式评估、开展受控 Prompt/RAG/语音实验

完成条件：

1. 教材范围按质量和进度逐步扩充，实际完成范围如实记录。
2. 正式测试集及人工评分规则冻结，不再用于调参。
3. 完成无 RAG/有 RAG、不同检索策略和不同 Prompt 的对照；检索策略与 Prompt 分别比较，单次实验避免同时改变多个因素。
4. 评估 ASR 误差等语音链路因素对检索和回答的影响。
5. 按正确性、完整性、依据一致性、表达适切性和资料不足处理汇总结果。
6. 保存可复查的配置、样本、评分和实验输出。

### E. 论文、截图、实验结果与验收记录整理

完成条件：

1. 论文中的系统范围、数据规模、版本和完成状态与仓库一致。
2. 架构图、流程图、界面截图和 API 示例来自实际系统。
3. 实验表格可追溯到真实测试集、配置和评分记录。
4. 补齐真实 AI、ASR、TTS、MySQL 和浏览器链路的验收记录。
5. 明确区分已完成、部分完成、未实现和未验证内容。
